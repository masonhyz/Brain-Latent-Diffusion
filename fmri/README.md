# fMRI data folder

Paired pre-/post-surgery CBF (cerebral blood flow) NIfTI volumes used by the
diffusion-model pipeline. This folder is **git-ignored** (except this README and
`qc.py`) — the actual scans are never committed, so anyone using the project has
to populate it locally following the layout below.

## Layout

```
fmri/
  pre_surgery/              # inputs:  pre-op CBF volumes
    <year>_<id>.nii.gz      # e.g. 2020_076.nii.gz
    ...
  6_months_post_surgery/    # targets: 6-month post-op CBF volumes
    <year>_<id>.nii.gz      # same filenames as pre_surgery
    ...
  qc/                       # generated by qc.py (git-ignored) — visual QC montages
  qc.py                     # QC script (tracked); run to (re)generate qc/
  README.md                 # this file
```

## Rules for storing data here

1. **Two folders, exact names.** Inputs go in `pre_surgery/`, targets in
   `6_months_post_surgery/`. These names are the dataset defaults
   (`moyamoya/dataset.py::PrePostFMRI`); change them only via the `--pre_dirname`
   / `--post_dirname` flags.
2. **One file per subject per folder**, gzipped NIfTI (`.nii.gz`).
3. **Filenames must match exactly across the two folders.** A subject is only a
   valid pair when `pre_surgery/<name>.nii.gz` **and**
   `6_months_post_surgery/<name>.nii.gz` both exist with the *same* filename.
   The dataset pairs by filename, and in the default `strict=True` mode it will
   raise if any file in one folder has no partner in the other.
4. **Naming convention:** `<year>_<id>.nii.gz`, where `<id>` is zero-padded to 3
   digits — e.g. `2024_007.nii.gz`. Keep the pre and post filenames identical
   (the year/id refer to the subject, not the scan date).
5. **Content:** each file is a single-delay CBF map
   (`CBF_Single_Delay_Pre_Diamox_standard_nonlin`) in standard space. Volumes may
   be 3D or 4D; the loader keeps whatever shape is in the file.

## Populating the folder

The canonical scans are reconstructed elsewhere and copied in by
`fmri/setup_data.py`, which pulls the matching pre/post CBF map for each
subject that has **both** available and writes them here with the
`<year>_<id>.nii.gz` naming above. A subject is skipped until both its pre and
post maps exist. If you are adding data by hand, follow the same rules.

## Quality control

`qc.py` renders one montage per subject (axial/coronal/sagittal mid-slices,
pre vs. post side by side) so you can flip through every pair and spot
degeneracies. From the project root:

```bash
python fmri/qc.py                       # all pairs -> fmri/qc/
python fmri/qc.py --max_items 10        # quick sanity check on the first 10
```

Defaults assume this folder is the data root and write PNGs to `fmri/qc/`
(a sibling of the two data folders). The `qc/` output is git-ignored.
